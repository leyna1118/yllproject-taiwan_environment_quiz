# 綠色旅遊測驗

第六屆堉璘臺大人才培育計畫｜Travel Green

一個線上小測驗：回答 8 個旅遊情境題，配對到一個**真實存在、現在就報得到名的在地綠色行動**（主線任務），加上兩條旅人性格光譜與三筆延伸資源。

**目標**：推行綠色旅遊
**問題**：多數人有環保意識，但旅遊時不知道當地有什麼環保資源可以參與
**受眾**：平常就會執行環保行為、想找環保旅遊點子的人

---

## 檔案結構

```
index.html               測驗本體（流程、計分、結果頁）
data/quiz-data.js        題目與資源資料（由 data.xlsx 自動產生，不要手改）
data.xlsx                內容的唯一真實來源，要改題目或資源請改這裡
tools/xlsx_to_js.py      轉檔腳本：data.xlsx → data/quiz-data.js
tools/apps-script.gs     匿名使用記錄的後端，部署到 Google Apps Script
result_page_example.html 結果頁的靜態範例（給設計討論用，不是產品的一部分）
legacy/                  v1 舊版測驗（護島人測驗），已停用，留著備查
```

直接用瀏覽器打開 `index.html` 就能跑，不需要架伺服器。

## 怎麼改內容

1. 打開 `data.xlsx` 改內容（分頁說明見下），存檔並**關閉 Excel**
2. 在專案根目錄執行：

   ```bash
   python tools/xlsx_to_js.py
   ```

3. 重新整理 `index.html` 就會看到新內容

腳本跑完會印出檢查結果。如果資料有問題（題數不對、選項對不到主線任務、分數分佈壞掉、某個主線任務沒有延伸資源等），會列出來提醒，照著回去修 `data.xlsx` 即可。

### data.xlsx 的分頁

| 分頁 | 用途 | 必要欄位 |
|---|---|---|
| `地區分類題` | Step 1，判斷使用者適合哪種地區類型（海邊／城市／鄉間／山林） | 題號、情境、選項、對應地區類型、備註 |
| `好玩活動題` | Step 2，判斷使用者適合該地區的哪一個主線任務，同時計算兩條光譜 | 地區、題號、題目、選項、對應主線任務（行政區）、知識派(-2)↔實踐派(+2)、深度(-2)↔廣度(+2) |
| `好玩活動` | 主線任務清單，**選擇欄標 V 的才會被採用** | 地區類型、行政區、環保類別、行動／資源名稱、一句話說明、連結、狀態、備註、選擇 |
| `延伸資源` | 結果頁下方的延伸資源，靠備註欄的「搭配主線任務：XXX」對應回主線任務 | 地區類型、行政區、環保類別、行動／資源名稱、一句話說明、連結、狀態、備註 |

其他分頁（`好玩活動(已驗證)`、`好玩活動(raw)`）是查證過程的存檔，程式不會讀。

**幾個要注意的規則**

- 每個地區類型要有 **4 個主線任務**（選擇欄標 V）、**4 題** Step 2 題目，每題 **4 個選項**
- Step 2 每題只服務一個維度：那一題的四個選項在該維度上要是 **+2 / +1 / −1 / −2 各一個**，另一個維度全部填 0
- 每個地區類型的 4 題裡，兩題走「知識派↔實踐派」、兩題走「深度↔廣度」
- `好玩活動題` 的「對應主線任務」可以寫簡稱（例如「花蓮」），腳本會在同一個地區類型裡對回全名（「花蓮縣新城鄉」）
- `地區分類題` 備註欄寫「平手決勝題」的那一題，會被當成 Step 1 平手時的決勝依據

## 測驗流程與計分

```
Step 1：地區分類題 4 題
   ↓ 選中的類型 +4、其餘三型各 +1，最高分者勝
   ↓ 平手 → 以「平手決勝題」的選擇為準；仍平手 → 以最後一題為準
   （這個結果不會顯示給使用者，畫面直接接到下一批題目）
Step 2：該地區類型的 4 題
   ↓ 選中的主線任務 +4、其餘各 +1，最高分者勝；平手以最後一題為準
   ↓ 同時累加兩條光譜（每條由 2 題貢獻，範圍 −4 ~ +4）
結果頁：「{行政區}．{環保類別對應的行動主題}之旅」
        ＋ 主線任務 ＋ 兩條光譜 ＋ 3 筆延伸資源
```

光譜位置換算：`(總分 + 4) ÷ 8 × 100`，得到 0～100 的位置。結果頁**只顯示傾向文字與圓點位置，不顯示分數數字**。

**使用者看不到地區類型的分流**——題幹四個地區類型共用同一組（出發前一晚 → 第一個上午 → 想怎麼跟朋友說 → 回程包包裡裝什麼），只有選項不同，所以從使用者的角度就是連續回答 8 題。

## 內容原則

- 主線任務優先收「**可以實際參加**」的行動（報名、租借、簽署、跟著地圖做），而不是只能看的組織官網
- 盡量避免商業旅行業者的單一產品，優先採用政府單位、國家公園、立案 NGO、社區發展協會主辦的行動
- 延伸資源以**同一個行政區、同一趟行程做得到**為第一優先，其次才是同環保類別的全國性資源
- 每一筆都要實際打開過連結查證，狀態欄記錄「已查證／待查證」

## 匿名使用記錄

`index.html` 會送三個事件（載入／開始／完成）到一個 Google Apps Script 端點，用來看有多少人測、測到哪裡放棄、結果分佈長怎樣。

**啟用方式**：照 `tools/apps-script.gs` 檔案開頭的步驟部署成 Web app，把網址貼進 `index.html` 最上方的 `TRACK_ENDPOINT`。**留空就完全不會送出任何記錄**，本機開發或還沒部署時不用擔心。

**只記錄這些，不含任何個資**：
- 一組存在瀏覽器 `localStorage` 的匿名亂數 ID（換裝置、清瀏覽器資料就會變成新 ID）
- 這個 ID 累計作答過幾次
- 完成測驗時的地區類型、主線任務、兩條光譜分數（0–100）
- 網址帶 `?test=1` 時會標記成「測試」來源，方便自己測試時跟真實數據分開看

不蒐集 IP、不放 cookie、不做瀏覽器指紋、沒有任何第三方分析套件。就算端點沒填、被瀏覽器擋掉、或使用者是無痕模式導致 `localStorage` 不能用，測驗畫面都會照常運作，不會出現任何錯誤。

**白名單驗證**：端點網址會出現在公開原始碼裡，`tools/apps-script.gs` 的 `doPost` 會擋掉格式不符的資料（欄位型別、範圍、事件與結果欄位是否一致等），只有通過驗證的資料才會寫進試算表。主線任務的白名單是從 `data/quiz-data.js` 手動抄出來的固定清單——**之後在 `data.xlsx` 改了主線任務，記得同步更新 `tools/apps-script.gs` 裡的 `VALID_ACTIVITIES`**，不然新的主線任務會被擋掉、不會被記錄。
